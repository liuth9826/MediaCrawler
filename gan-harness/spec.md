# gan-harness spec — 穿搭趋势分析

来源：`docs/穿搭趋势-SDD.md`（GATE 1 已批准）。
本文件是生成器/评估器共用的裁决依据。切片 1 的验收范围见下，其余为路线图。

## 目标

基于 MediaCrawler 既有采集能力，自动发现高传播的穿搭帖子与博主，采集信息并做内容分析，
产出穿搭趋势。

## 切片 1 的验收范围（本次）

`uv run python -m trend run --keywords 穿搭` 必须走通：
**发现 → 采集（复用既有 XHS 搜索爬虫）→ SQLite 存档 → 综合传播分 → Markdown 报告**。

必须满足：

- **S1 复用而非重写**：通过子进程调用既有 `main.py --type search`，不新建爬虫。
- **S2 综合传播分**：`raw = 5×share + 3×collected + 2×comment + 1×liked`，`composite = log1p(raw)`；
  原始分与压制分、以及 `score_formula_version` 一并落库。
- **S3 幂等**：重复运行不得产生重复行；`TrendPostScore.note_id` 唯一；
  `first_seen_run_id` 跨运行保持稳定。
- **S4 批次记账**：每次运行写 `trend_crawl_run`，含退出码、运行状态（失败必须记 `failed`）、库内条目数、新增/更新数、错误行数、可信度与判定依据。可信度阈值用**绝对条数**而非比率。
- **S5 报告**：Markdown，含运行信息、批次可信度、采集与入选统计、**风格结论分区**、Top-N 榜单。
- **S6 无模型依赖**：`trend report --run-id` 只读存档即可重建报告，全程零模型调用。
- **S7 脏值健壮**：`"None"`（`str(None)` 落库）、`"1.2万"`/`"1亿"`、`"null"`、毫秒时间戳
  都必须被正确规范化。
- **S8 后端守卫**：非 DB 后端（csv/json/jsonl）必须明确拒绝；CLI 需能把后端设为 DB。

## 质量底线（全切片适用）

- **Q1 不臆造**：无图片证据不下风格结论。切片 1 必须在报告里**显式声明不产出风格结论**，
  并点名 `text_only` / `image_backed` 两个证据等级。
- **Q2 可信度可判定**：能区分「整批采集不完整」与「个别内容失败」。整批不完整时报告头部告警；
  阈值内的个别失败不得否定整批。
- **Q3 可版本化**：打分公式版本、后续的分析版本必须随结果落库，升级后新旧可区分。

## 边界

- 不做 WebUI。
- 切片 1 只打通 `xhs`；其余平台须明确报错而非静默出错。
