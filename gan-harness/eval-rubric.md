# gan-harness eval-rubric — 穿搭趋势分析

评估对象：切片 1 的实现（`trend/` 包 + `tests/test_trend_*.py`）。
通过阈值：加权总分 **≥ 7.0 / 10**。
模式：`code-only`（本切片无 UI，边界明确不做 WebUI）。

每条 1–10 分，按权重加权求和。评分必须引用具体文件与行号作为证据；
不得凭印象打分，也不得因为「测试通过」就给满分 —— 测试通过只是入场券。

## 维度与权重

### 1. 需求覆盖（25%）

逐条核对 `gan-harness/spec.md` 的 S1–S8。

| 分档 | 判据 |
|------|------|
| 9–10 | S1–S8 全部有实现且可指认；无遗漏、无空壳 |
| 7–8 | 覆盖 S1–S7，S8 或 S5 有瑕疵 |
| 5–6 | 主链路可跑，但有一项验收项缺失 |
| ≤4 | 主链路不可跑，或采集/存档未复用既有能力 |

### 2. 质量底线落实（25%）

Q1/Q2/Q3 必须是**结构上被强制**的，不是靠注释或自觉。

| 分档 | 判据 |
|------|------|
| 9–10 | 三条都在数据结构与代码路径上可验证；报告显式声明不产出风格结论；个例失败与整批失败有可区分的数据模型 |
| 7–8 | 三条都实现，但某条只体现在报告文案、未落到数据模型 |
| 5–6 | 仅实现了其中两条 |
| ≤4 | 存在无证据的风格断言，或失败率与整批完整性无法区分 |

### 3. 可复跑与幂等（20%）

| 分档 | 判据 |
|------|------|
| 9–10 | 重复运行零重复行；首次出现时间稳定；报告可离线重建且渲染路径不触及模型；有测试证明 |
| 7–8 | 幂等成立，但离线重建只覆盖部分报告内容 |
| 5–6 | 幂等依赖调用方不去重，或重建会触发采集 |
| ≤4 | 重复运行产生重复数据 |

### 4. 真实数据健壮性（15%）

必须覆盖真实落库形态：`str(None)` → `"None"`、中文单位计数、`json.dumps` 的 `"null"`、
毫秒时间戳、负数与乱码。

| 分档 | 判据 |
|------|------|
| 9–10 | 上述形态全部被规范化且有针对性测试；解析失败不抛异常 |
| 7–8 | 覆盖大部分，个别形态会静默变成 0 而未标注 |
| 5–6 | 只处理了常规数值 |
| ≤4 | 脏值会导致崩溃或产生负数/错误排名 |

### 5. 测试与类型（10%）

| 分档 | 判据 |
|------|------|
| 9–10 | 关键分支（含失败与降级路径）都有断言；新增代码通过 mypy；无未处理告警 |
| 7–8 | 覆盖主链路与部分边界 |
| 5–6 | 只有 happy path |
| ≤4 | 无测试，或测试断言的是实现细节而非行为 |

### 6. 明晰性（5%）

| 分档 | 判据 |
|------|------|
| 9–10 | 命名自解释；注释只解释「为什么」；模块职责边界清楚 |
| 7–8 | 基本清晰，个别地方需要读实现才能理解意图 |
| ≤5 | 注释复述代码，或模块职责混杂 |

## 一票否决项

出现以下任一情况，无论总分高低，直接判不通过：

- 出现没有图片证据支撑的风格 / 元素结论（违反 Q1）。
- 采集失败时报告仍声称批次完整（违反 Q2）。
- 为通过评估而弱化或删除既有测试。
- 命令拼接使用 `shell=True` 或等价方式，使关键词 / 平台名可注入 shell。
